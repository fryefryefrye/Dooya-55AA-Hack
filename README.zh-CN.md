# 杜亚 55 AA TTL 协议

杜亚（Dooya）电动卷帘电机私有 `55 AA` TTL 协议的逆向记录，用来甩掉官方转换模块，直接用
ESP8266 / ESP32 驱动电机。

## 1. 项目背景

杜亚的电机套装里通常附一个小转换模块（如 `DC1545W`）。这类小模块有很多变种——不同的平台、
不同的语音助手、不同的无线方案——但电机本身只有一种 SKU，说的始终是同一套语言。485 转换模块
只是本文的例子：它对外是标准 RS485，跑**杜亚统一串口协议**（官方公开发布文档的
`55 FE FE` 帧格式）；但在内部，它把协议**悄悄翻译**
成私有的 `55 AA` TTL 短帧丢给电机。

<img src="img/motor.jpg" width="25%" alt="电机、6P 线缆与官方 485 转换模块"/>

*`DVQ24WN` 电机、6P 线缆与官方 RS485 转换模块——同一台电机配过的众多转换模块变种之一。*

后果很直接：把单片机接到电机的水晶头上、发官方统一串口协议（`55 FE FE`）的帧，电机会**完全不理会**——
既没有错误码，也没有任何回应。

本仓库把这套私有协议完整拆开：帧格式、最容易算错的 CRC-16、控制指令、位置查询、
主动状态上报，足够直接对话电机，并接入 Home Assistant / ESPHome 或任何自建系统。

下文每一个数字都是在官方适配器与电机之间挂逻辑分析仪抓出来的，没有一处是从手册猜的。
示例代码会把线上报文原样打印出来，上机前先拿它核一遍自己的设备，再信任下面的表格。

## 2. 适用范围

在 6P 水晶头（RJ11 类）线缆的电机上验证过：

* 电动卷帘
* 电动蜂巢帘 / 风琴帘
* 电动百叶帘（角度字节有效）
* 电动斑马帘 / 日夜帘

参考型号：`DVQ24WN`、`DVQ24AF` 以及其它杜亚代工电机。
如果你的电机配的是 `DC1545W` 这类转换模块，大概率就是这套协议——上机前
最好用逻辑分析仪或串口监听先验一次。

## 3. 硬件：绕开转换模块

### 3.1 接线

在电机的水晶头上直接挂一块小小的 ESP8266 即可——电机自带的 3.3V 电源可以直接驱动它，
无需另外供电。**TX / RX 必须交叉**。

| 电机信号 | 单片机（示例） | 备注 |
| :--- | :--- | :--- |
| 电机 RX | **TX**（D7 / GPIO13） | 单片机发，电机收 |
| 电机 TX | **RX**（D6 / GPIO12） | 电机发，单片机收 |
| GND | **GND** | 必须共地，否则收不到任何东西 |
| 3.3V 输出 | — | 可直接给挂在水晶头上的小 ESP8266 供电 |
| KEY UP | 悬空 | 短接到 GND 触发上行 |
| KEY DOWN | 悬空 | 短接到 GND 触发下行 |

转换模块 RJ11 插座的引脚定义——电机的水晶头就插在这个座上，线色见图中标注：

![转换模块 RJ11 插座引脚定义](img/rj11.png)
*从左到右：`KEY_DOWN`、`KEY_UP`、3.3V 输出、`GND`、`RXO`（电机收）、`TXO`（电机发）。*

两个按键线是退路：万一你的机型说的是别的方言，短接到 GND 仍然能把窗帘动起来，
可以当作不要位置反馈时的备用方案。

### 3.2 串口参数

**9600 8N1**。帧与帧之间至少留 3.5 个字符时间（约 3.65 ms，保险起见按 6 ms 判），
收帧的帧尾判定同理。

> ESP8266 注意：`D6` 是 `GPIO12`（MTDI），属于启动引导脚——上电时若被电机的 TX 线拉高，
> 部分模块会启动失败（芯片会按 1.8V Flash 供电启动）。遇到这种情况，让电机比单片机晚上电，
> 或把线换到别的脚。

## 4. 帧结构

| 字节 | 字段 | 说明 |
| :--- | :--- | :--- |
| 0 | 起始码 | 固定 `0x55` |
| 1 | 起始码 | 固定 `0xAA` |
| 2 | 长度 | 从功能码到 **CRC 低字节** 的字节数（= 整帧长度 − 3） |
| 3 | 功能码 | `0x01` 控制，`0x02` 查询 / 查询应答，`0x03` 主动状态上报 |
| 4 … N-2 | 数据区 | 随功能码变化 |
| N-1, N | CRC16 | **高字节在前、低字节在后** |

最短的帧 7 字节（`0x55 0xAA 0x04 0x02 0x02 …`），抓到过最长的是 15 字节（状态上报）。
示例 —— “打开”，整帧 8 字节，长度字段 `0x05`：

```
55 AA 05 01 01 01 EA A9
 |  |  |  |  |  |--+-- CRC16 = 0xEAA9
 |  |  |  |  |-+----- 通道 / 设备地址（01 01）
 |  |  |  |--+------- 动作码（01 = 打开）
 |  |  |--+--------- 功能码（01 = 控制）
 |  |--+----------- 长度
 +--+------------- 起始码
```

## 5. CRC-16

这是绝大多数实现会算错的地方，单独成节。

### 5.1 参数

| 参数 | 值 |
| :--- | :--- |
| 宽度 | 16 |
| 多项式 | `0x8005` |
| 初值 | `0xFFFF` |
| 输入反射（refin） | **否** —— 按 MSB 先行喂入 |
| 输出反射（refout） | **否** |
| 最终异或（xorout） | `0x0000` |
| 校验范围 | `0x55` … 最后一个数据字节（含起始码，不含 CRC 自身） |
| 帧内字节序 | **高字节在前**，低字节在后 |
| 校验值（`"123456789"`） | `0xAEE7` |

`0xAEE7` 这个 check 值说明它正是通常所说的 **CRC-16/CMS** 参数组。

### 5.2 它不是 Modbus CRC

多项式与 CRC-16/MODBUS 相同（都是 `0x8005`），所以很多人直接套一个 Modbus CRC 函数，
然后奇怪电机为什么一声不吭。三处区别：

| | 杜亚 55AA | CRC-16/MODBUS |
| :--- | :--- | :--- |
| 输入反射 | 否（MSB 先行） | 是 |
| 寄存器反射 | 否 | 是 |
| 帧内 CRC 字节序 | 高字节在前 | 低字节在前 |

三条里错任意一条，帧看起来都很正常（长度字段也对），但电机就是静默丢弃。

### 5.3 参考实现

无第三方依赖的实现放在 [`crc/`](crc)：

* [`crc/dooya_crc.h`](crc/dooya_crc.h) / [`crc/dooya_crc.c`](crc/dooya_crc.c) —— C：
  `dooya_crc16()` 计算 CRC，`dooya_frame_finish()` 直接把 CRC 追加到帧体后面
* [`crc/dooya_crc.py`](crc/dooya_crc.py) —— Python，自带自测：`python3 dooya_crc.py`

9600 波特下逐位算完全够用（16 字节帧 = 128 次循环）。若要查表版，
按 `refin = refout = false` 生成表即可。

### 5.4 测试向量

标 _抓包_ 的是从官方适配器与电机之间实测取的；其余由参考实现算出，方便对照移植是否写对。

| 含义 | 完整帧（十六进制） | 来源 |
| :--- | :--- | :--- |
| 查询位置 | `55 AA 04 02 02 38 74` | 抓包 |
| 打开 | `55 AA 05 01 01 01 EA A9` | 抓包 |
| 关闭 | `55 AA 05 01 01 02 EA A3` | 抓包 |
| 停止 | `55 AA 05 01 01 03 6A A6` | 抓包 |
| 设置位置 50 % | `55 AA 06 01 02 32 67 00 9A` | 抓包 |
| 设置位置 0 % | `55 AA 06 01 02 00 67 2C 99` | 计算 |
| 设置位置 1 % | `55 AA 06 01 02 01 67 AA 9A` | 计算 |
| 设置位置 100 % | `55 AA 06 01 02 64 67 74 9F` | 计算 |
| 查询应答：当前位置 50 % | `55 AA 05 02 02 32 E0 3F` | 抓包 |
| 上报：关闭中，0 % | `55 AA 0C 03 01 02 00 0B 01 00 02 00 00 DB 3B` | 抓包 |
| 上报：准备停，50 % | `55 AA 0C 03 01 03 32 B4 01 00 02 00 00 D2 A9` | 抓包 |
| 上报：微调中，50 % | `55 AA 0C 03 01 01 32 A9 01 00 02 00 00 2A BB` | 抓包 |
| 上报：稳定，50 % | `55 AA 0C 03 01 03 32 64 01 00 02 00 00 52 77` | 抓包 |

### 5.5 收帧校验步骤

1. `buf[0] == 0x55 && buf[1] == 0xAA`，否则丢弃并重新找帧头。
2. `frameLen = buf[2] + 3`；帧可能被拆成几段到达，等够 `frameLen` 字节再判。
   如果线路已静默超过 6 ms 而字节数还不够，说明这帧被截断了，丢弃。
3. `recvCrc = (buf[frameLen-2] << 8) | buf[frameLen-1]` —— 再强调一次：**高字节在前**。
4. `recvCrc == dooya_crc16(buf, frameLen - 2)`。

调试时把 `recvCrc` 和算出的值并排打日志，是最快定位“反射或字节序搞错”的办法：
写错的移植会出现稳定的固定差异，而不是随机噪声。

## 6. 指令（主机 → 电机）

| 动作 | 帧 |
| :--- | :--- |
| 打开（上行） | `55 AA 05 01 01 01 EA A9` |
| 关闭（下行） | `55 AA 05 01 01 02 EA A3` |
| 停止 | `55 AA 05 01 01 03 6A A6` |
| 设置位置 | `55 AA 06 01 02 <百分比> 67 <crc_h> <crc_l>` |
| 查询位置 | `55 AA 04 02 02 38 74` |

* `<百分比>` 为 `0x00` … `0x64`（0–100 %），十六进制。
* `0x67` 在卷帘上观察到是固定值，推测是百叶帘的角度参数。除非你有别的依据，保持 `0x67`。
* `01 01` 是通道 / 设备地址，所有抓包里都是 `01 01`。
* 控制帧电机**不做确认**，唯一的反馈是随后到来的状态上报，或者你自己去查位置。

## 7. 应答与上报（电机 → 主机）

**查询应答** —— `55 AA 05 02 02 <位置> <crc_h> <crc_l>`

这一帧里**没有状态字节**。想知道“在不在动”，只能连续查询并比较位置变化。

**主动状态上报** —— `55 AA 0C 03 01 <状态> <位置> <角度> 01 00 02 00 00 <crc_h> <crc_l>`

| 状态 | 含义 |
| :--- | :--- |
| `0x01` | 打开中（上行） |
| `0x02` | 关闭中（下行） |
| `0x03` | 停止 / 到达限位 / 待机 |

状态字节是权威信息，能拿到就别靠位置变化去猜。最后几个百分点附近，电机会在 `0x03` 和
`0x01` 之间来回跳着做微调，这属于正常现象。

角度字节对百叶帘有效，对卷帘是噪声。末尾 5 个数据字节（`01 00 02 00 00`）在所有抓包里
都没变过，这里直接忽略。

电机会在运动过程中和停下后主动上报，但**空闲时不会周期上报**——所以控制器仍然需要自己轮询。

## 8. 软件架构

### 8.1 接收

* `SoftwareSerial`，9600 8N1（有空闲硬件串口就用硬件串口）。
* 靠线路静默判帧：最后一个字节之后 6 ms（9600 下 3.5 个字符时间）把缓冲区当成一帧。
* 解析前先在缓冲区里搜索 `0x55 0xAA`，避免前面粘的噪声把整帧废掉。
* 再查长度字段和 CRC。校验不过就整帧丢弃，绝不“半帧解析”。
* 缓冲区 64～256 字节足够，最长帧只有 15 字节。

### 8.2 解析流程

1. 整帧校验（起始对、长度、CRC-16）。
2. 按功能码分支：
   * `0x02`，8 字节 → 查询应答，位置在 `buf[5]`；
   * `0x03`，15 字节 → 状态上报，`buf[5]` 状态、`buf[6]` 位置、`buf[7]` 角度；
   * `0x01` 是主机发的，电机一般不会回显。
3. 位置直接就是百分比（`0x00`–`0x64` = 0–100），无需换算。
4. 输出状态：有上报就用上报的状态字节，没有就用位置变化趋势推断。

### 8.3 位置、状态与轮询

| 问题 | 答案 |
| :--- | :--- |
| 位置怎么拿？ | 发 `55 AA 04 02 02 ...`，读应答的 `buf[5]`。每秒查一次就够，再快电机也不会更快回应。 |
| 怎么知道在动？ | 有状态上报就用状态字节；只有应答时看位置趋势，连续几秒不变再判为停止。 |
| 空闲时会主动上报吗？ | 不会，必须轮询。 |
| 最后几个百分点为什么乱跳？ | 电机在末端做微调，`0x03` 与 `0x01` 会交替出现。把状态变化做 1 秒左右的去抖，或者直接比较位置与目标值。 |

所以一个控制器只需要三件事：周期性查位置、一条能解析上报的接收路径、一条一次只发一帧
（帧间隔 6 ms）的发送路径。

## 9. 示例代码

[`examples/dooya_55aa_controller/`](examples/dooya_55aa_controller/README.md) 下是一个自包含的
Arduino 工程（ESP8266），普通 `.ino` 放在目录根，可直接用 Arduino IDE 打开，也可用 PlatformIO 编译。

全部功能都在这一个工程里：

| 功能 | 做法 |
| :--- | :--- |
| 控制指令 | 串口控制台：`o` 开、`c` 关、`s` 停、`p50` 设位置、`q` 查位置 |
| 位置轮询 | 空闲时每秒查一次，随时知道当前百分比 |
| 应答与上报 | 先校验（起始对、长度、CRC），再解析出位置与状态 |
| 状态判断 | 有上报就用状态字节，没有就按位置趋势推断 |
| 报文打印 | 收发的每一帧都打十六进制，运行时按 `d` 开关 |

引脚约定与第 3 节一致（`D6` = 电机 TX、`D7` = 电机 RX、9600 8N1），接线表照旧适用。
命令表、示例输出和可调参数见该目录自己的 README。
